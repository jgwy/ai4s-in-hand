# 可复现性规范

可复现不是“在作者电脑上再跑一次”。教程必须让读者知道输入是什么、环境是什么、执行了什么、预期看到什么，以及结果偏离时怎样诊断。

## 最小复现包

每个核心实验至少提供：

```text
问题与评价标准
├── 数据来源、版本、许可证与校验值
├── 环境与依赖锁定
├── 数据处理和划分代码
├── 简单基线与核心模型
├── 配置、随机种子和运行命令
├── 预期指标范围与资源消耗
├── 失败案例和排查路径
└── 图表生成与结论映射
```

## 环境与依赖

- 明确最低 Python、Node.js 和主要框架版本；
- 提交依赖声明和 lockfile，不依赖作者机器上的全局包；
- 若 CPU 与 GPU 使用不同依赖或算法路径，分别写明；
- 不把容器当作唯一复现方式；提供 OrbStack/Docker 兼容命令时，也保留无容器的核心路径；
- 依赖安全告警先记录影响范围，不在没有回归验证时盲目升级大版本。

## 数据

大型数据不直接提交到 Git。每个数据集需要：

| 项目 | 要求 |
| --- | --- |
| 来源 | 官方下载页、稳定 URL 或永久标识 |
| 版本 | 发布号、发布日期或快照时间 |
| 许可证 | 允许的使用和再分发范围 |
| 完整性 | SHA-256 等校验值 |
| 样本单位 | 一个样本在科学上代表什么 |
| 划分 | 随机、时间、骨架、空间、实验批次或其他逻辑 |
| 处理 | 过滤、去重、缺失值和异常处理步骤 |

下载脚本必须在写入前校验目标位置，避免覆盖用户文件；网络不可用时，提供小型合成数据或预计算结果用于理解流程。

## 随机性与结果范围

固定随机种子有助于调试，却不能证明方法稳定。根据实验成本选择：

- 教学烟雾测试：固定一个种子，验证流程能运行；
- 核心比较：使用多个预先声明的种子，报告均值、离散程度和失败次数；
- 序贯优化：固定候选池与初始预算，保存每一步选择和观测历史；
- 非确定性 GPU 算子：记录硬件、驱动和框架设置，允许在合理范围内波动。

文档报告“预期范围”，例如验证 MAE 通常落在某个区间，而不是要求最后一位小数完全相同。范围必须来自实际运行，不凭经验猜测。

## 基线与消融

每个高级方法至少和一个简单基线比较：

- 性质预测：均值、线性模型或树模型；
- 序贯筛选：随机选择与简单贪心；
- PDE 代理：低分辨率数值方法或朴素神经网络；
- 文献综合：明确检索式的人工证据表；
- Agent 工作流：固定脚本或人工检查清单。

消融实验用于回答“新增组件带来了什么”，不能用来堆积表格。提前写出假设、比较条件和判定标准。

## 外部服务与密钥

外部 API 不是核心实验的隐含前提。使用时必须：

1. 通过环境变量读取密钥；
2. 提供不含真实值的 `.env.example`；
3. 将 `.env.local`、缓存响应和含隐私的日志排除在 Git 之外；
4. 不在 Notebook 输出、截图、报错或实验跟踪平台记录密钥；
5. 记录服务名称、接口版本、调用日期和非确定性；
6. 提供静态示例响应或人工流程作为降级路径。

加载本地变量的示例：

```bash
set -a
source .env.local
set +a
```

不要在命令行中直接写出密钥值，因为命令可能进入历史或进程列表。

## 实验记录

每次产生教程结论的运行，应保存：

- Git 工作树或发布版本标识；
- 运行时间、环境与硬件；
- 输入数据版本和校验值；
- 配置与随机种子；
- 标准输出、错误和退出码；
- 指标、图表与原始结果位置；
- 人工修改、中断和失败原因。

未提交草稿可以记录工作树 diff 标识，不应为了获得 commit ID 而提前提交未经审阅内容。

## CPU、GPU 与离线降级

| 能力 | 核心路径 | 扩展路径 | 降级路径 |
| --- | --- | --- | --- |
| 模型训练 | CPU 可完成的小数据和少量 epoch | GPU 完整训练 | 加载预训练权重或结果表 |
| 数据获取 | 固定小样本或下载脚本 | 完整公开数据集 | 合成数据与缓存元数据 |
| 文献检索 | 手工检索式与 DOI 清单 | 论文搜索 API | 提供已核验的最小文献包 |
| 闭环实验 | 候选池虚拟实验 | 远程模拟器或设备 | 回放固定实验轨迹 |

降级路径可以缩小规模，但不能改变要学习的核心判断。例如，回放实验轨迹仍要让读者执行候选选择、预算控制和停止判断。

## 发布前检查

- [ ] 从干净环境安装依赖成功；
- [ ] 核心 Notebook 自上而下运行，无隐藏状态；
- [ ] 数据下载、校验与许可证说明完整；
- [ ] 基线和核心方法使用相同划分与预算；
- [ ] 图表可由代码重新生成；
- [ ] 结果落在文档声明的预期范围；
- [ ] 网络、GPU 和 API 失败时存在降级路径；
- [ ] Git 中没有密钥、个人数据、大型缓存或绝对路径；
- [ ] 失败案例与限制和成功结果一同发布。
