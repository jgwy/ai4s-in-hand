# 第 16 章：自主科学发现闭环

> [!CAUTION]
> 本章只使用虚拟实验和系统架构，不提供真实危险实验的操作、条件或设备控制。所谓“自治”始终限定在人工定义的目标、动作空间、数据源、预算和停止条件内；它不等于科学发现已经成立。

把文献、模型、模拟器和执行器连接成循环，并不会自动得到知识。循环可能优化错目标、把传感错误当新现象，或者在代理指标上持续进步却离科学问题越来越远。自主系统的首要问题不是“能调多少工具”，而是系统边界、证据更新和责任是否清楚。

## 本章解决的问题

完成本章后，你应该能够：

1. 用感知—建模—规划—执行—反馈描述闭环；
2. 写清目标、动作空间、资源预算、停止规则和人工接管点；
3. 区分自动化、有限自治与经独立证据支持的发现；
4. 判断单 Agent 与多 Agent 架构的真实增益和新增风险；
5. 在虚拟候选池中运行可暂停、可回放的闭环；
6. 交付系统边界图和故障模式与影响分析（FMEA）。

## 核心概念

### 16.1 闭环的六个状态

```text
已有证据 E_t → 信念/模型 B_t → 候选计划 P_t → 风险与证据闸门 G_t
       ↑                                                  ↓
   更新与审查 ← 虚拟观测 O_t ← 受限执行动作 A_t
```

- **证据 $E_t$：**文献、数据、失败与版本记录；
- **信念 $B_t$：**竞争假设的权重、代理模型和不确定性；
- **计划 $P_t$：**下一批虚拟计算或查询；
- **闸门 $G_t$：**预算、允许域、质量、安全和人工审批；
- **动作 $A_t$：**白名单中的虚拟操作；
- **观测 $O_t$：**带质量码与来源的反馈。

只有 $O_t$ 通过质量门，才进入下一轮。模型输出和工具日志不是天然证据。

### 16.2 教学用自治等级

下表是本教程的操作性分类，不是通用行业标准：

| 等级 | 下一步由谁决定 | 允许范围 | 合理称呼 |
| --- | --- | --- | --- |
| L0 | 人工 | 单次分析 | AI 辅助 |
| L1 | 固定脚本 | 预设序列 | 自动化 |
| L2 | 算法提议、人工批准 | 白名单虚拟动作 | 人在环决策 |
| L3 | 算法执行、异常时人工接管 | 固定目标、预算和停止规则 | 有限自治 |
| L4 | 系统可在批准范围内调整子目标 | 仍有不可越过的治理边界 | 扩展自治研究原型 |

即使达到 L3/L4，也只描述系统如何决策。**发现**还要求新颖主张、独立复核或外部有效性确认、竞争解释处理和共同体审查；这里不是仅指“实现是否正确”的 verification。

### 16.3 目标、停止条件与“无结论”

闭环开始前固定：

- 主要科学问题与代理目标；
- 允许查询、禁止动作和单轮/总预算；
- 数据质量最低条件与不确定性阈值；
- 成功、无结论、异常和安全停止条件；
- 重新开放闭环所需的人类证据。

停止不是失败处理的附属项。预算耗尽、连续若干轮无信息增益、模型校准失效、候选越出适用域或 competing hypotheses 无法区分，都应允许以“无结论”结束。

### 16.4 多 Agent 只在职责可分时成立

可把检索、代码、规划、验证分别交给 Agent，但必须有共享事件账本、明确输入输出、冲突处理和最终责任人。多 Agent 的简单基线是同一个固定工作流加人工检查清单。评价增益看：

- 是否提高独立错误检出，而非让多个模型互相附和；
- 是否减少端到端时间而不牺牲 provenance；
- 冲突是否显式暴露；
- 通信和权限是否引入新失败面。

“投票一致”不是事实核验；模型可能共享训练数据、提示和系统性偏差。

### 16.5 新成果必须限定任务范围

2026 年 Nature 论文 *Towards end-to-end automation of AI research* 报告了在**计算型机器学习研究**中自动生成想法、代码、实验和论文的系统。研究团队仍在多个阶段人工筛选候选输出，并按主题符合度、实现正确性和格式选择三篇投稿；其中仅一篇超过一个录取率约 70% 的 ICLR workshop 的平均人类录取门槛，三篇均未达到 ICLR 主会标准。作者同时报告实现错误、浅显想法、引用幻觉以及不稳定达到 workshop 标准等限制（[Lu et al., 2026](https://doi.org/10.1038/s41586-026-10265-5)）。这支持“有界计算研究流程的较多环节可被自动化并接受人工筛选”的主张，不支持“开放世界科学已可无人可靠完成”，更不能外推到实体实验安全。

早期 Robot Scientist 工作也展示了在预定义生物学任务中自动形成和测试功能基因组学假设的闭环原型（[King et al., 2009](https://doi.org/10.1126/science.1165620)）。这些系统是研究对象与工程证据，不是自治等于发现的定义。

## 可检查产物：系统边界图与虚拟闭环

### 16.6 系统边界卡

```markdown
【自主闭环边界卡】
- 科学问题与竞争假设：
- 输入证据及版本：
- 允许动作：仅候选池查询 / 仅批准模拟器配置
- 明确禁止：真实设备控制、外部写入、改变主要指标、扩大候选域
- 单轮和总预算：
- 成功 / 无结论 / 异常停止：
- 必须人工批准：首次运行、范围变更、异常恢复、最终主张
- 责任人：科学 / 软件 / 数据 / 安全 / 发布
```

### 16.7 虚拟闭环流程

沿用第 15 章候选池，循环最多执行预定轮数：

1. 读取不可变账本并校验数据版本；
2. 更新代理模型与竞争假设摘要；
3. 由固定策略或 Agent 提议下一批；
4. 验证器检查重复、预算、适用域和禁止列表；
5. L2 模式等待人工批准，L3 教学模式仅对合规虚拟动作自动执行；
6. 虚拟 oracle 返回结果与质量码；
7. 独立分析器决定接受、隔离或停止；
8. 记录选择理由、未选候选、失败和信念更新；
9. 检查成功、无结论与异常停止条件。

### 16.8 简单基线与评价

**固定脚本基线：**预先写死查询序列、分析步骤和停止轮数，不根据反馈调整。与闭环策略使用同一候选池、初始数据和预算。比较：

- 达到目标阈值的查询数及区间；
- 对竞争假设的信息增益代理；
- 失败、违规提案和人工接管次数；
- 从最终主张回放到原始观测的成功率；
- 端到端资源和时间。

如果自治策略只增加工具调用，未改善证据质量或决策效率，就没有超过固定脚本。

### 16.9 FMEA 最小表

| 失效模式 | 可能影响 | 检测 | 预防/缓解 | 自动动作 | 人工责任 |
| --- | --- | --- | --- | --- | --- |
| oracle 标签错位 | 模型学习错误对应 | ID/校验值不一致 | 端到端身份约束 | 停止、隔离本轮 | 数据负责人复核 |
| 代理不确定性失准 | 反复选错区域 | 校准与覆盖监控 | 简单基线、适用域门 | 降级为固定策略 | 科学负责人决定恢复 |
| 规划器越权 | 超预算或越出范围 | 白名单闸门 | 最小权限 | 拒绝并暂停 | 安全负责人审查 |
| 多 Agent 相互确认错误 | 假共识 | 独立来源与异构检查 | 禁止以投票代替证据 | 标记冲突 | 人类裁决并留痕 |
| 停止条件漂移 | 选择性延长研究 | 配置快照差异 | 条件预登记 | 不加载新配置 | 项目负责人审批变更 |

## 常见错误与失败模式

| 现象 | 根因 | 诊断与修复 | 不能推出 |
| --- | --- | --- | --- |
| 循环一直运行 | 无“无结论”或异常停止 | 预登记预算、信息和安全条件 | 持续运行终会发现 |
| 奖励上升但科学目标不变 | 代理目标错位 | 回到主张—证据映射 | 优化成功即知识增加 |
| Agent 自己审自己 | 验证器缺乏独立性 | 固定测试、独立数据和人工闸门 | 自我反思即核验 |
| 多 Agent 一致 | 共享偏差造成相关错误 | 异构来源、冲突任务和人工复查 | 共识即真值 |
| 人工接管没有记录 | 把人类修复隐藏为自治能力 | 记录触发、操作与恢复依据 | 演示全自动 |
| 把有界基准外推到科学整体 | 忽略对象、动作和评价范围 | 明确自治包络与未覆盖环节 | 某领域原型通用成立 |

## 科学有效性与证据检查

- [ ] 是否明确所有执行均为虚拟操作，且禁止真实设备控制？
- [ ] 目标、动作空间、预算、停止和接管是否在运行前冻结？
- [ ] 感知、模型、规划、闸门、执行与更新能否分别测试？
- [ ] 竞争假设是否随证据更新，而非只优化单一分数？
- [ ] 是否有固定脚本基线，并使用相同资源与数据？
- [ ] 多 Agent 是否证明了独立增益并记录冲突、权限与通信失败？
- [ ] 人工修改、暂停和否决是否完整进入账本？
- [ ] “自治”是否只描述系统属性，“发现”是否保留给经独立复核或外部有效性确认的主张？

## 练习与评价要点

1. **概念辨析：**分别给一个 L1、L2、L3 系统，说明为什么等级不是“智能分数”。评价要点：依据下一步决策权、动作范围和接管，而非模型大小。
2. **失败诊断：**闭环连续改进代理目标但独立指标下降。评价要点：识别目标错位、触发停止、回滚到固定脚本、不得选择性删除轮次。
3. **迁移实践：**为动力系统代理建立边界卡。评价要点：仅虚拟模拟、参数域、外推停止、残差/误差双指标和人工批准齐全。
4. **新成果审读：**阅读 Lu et al. 2026 的摘要与限制。评价要点：准确写出领域、评价设置、人工筛选、成功比例和不能外推的能力。

## 本章小结与下一步

自主闭环的能力来自受约束的反馈决策，可信度来自独立复核、外部有效性确认、停止条件和可回放账本。下一章把闭环输出转化为研究论证，要求每个文字主张连接到数据、代码或文献，并披露 AI 与人工的实际贡献。
